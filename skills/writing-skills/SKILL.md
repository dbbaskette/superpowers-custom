# Maintain useful skills

Describe the capability and actual trigger briefly. Preserve user scope, tool/provider choice,
authorization boundaries, and important domain invariants. Avoid universal process demands
based on one incident. Keep simple skills self-contained; route substantial conditional modes
to references so unrelated detail is not loaded.

Use the current skill-creator when available for metadata/schema details. Do not force a TDD
skill load or delete valid work merely because no prior failing scenario exists. Group related
instruction changes so conflicting rules are corrected together.

Validate frontmatter, local links, scripts, and packaging. For meaningful behavior changes,
run realistic independent scenarios with minimum raw context and safe side-effect boundaries;
include counterexamples and prior behavior where useful. Preserve transcripts and judge actual
outcomes, not echoes of desired wording. Small edits need not trigger a fixed number of model
runs. No paid API or extra credentials are required merely to author a skill.

Inspect callers before removing resources. Keep reusable scripts and domain references, but
do not automatically route to obsolete process recipes. Report what was tested and limitations.
Publish or install only within the user’s authorization; upstream synchronization should be
reviewed and versioned, not overwrite local customizations silently.
